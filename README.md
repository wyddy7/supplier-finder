# Поиск поставщиков для кухни

Прототип сервиса, который помогает ресторану найти поставщиков (упаковку, овощи, мясо, рыбу, молочку) в своём городе, сравнить их и решить, кому звонить первым.

- **Прототип:** https://claude.ai/artifact/Y3ABnsryxz23G13W1EUWFu (видео на минуту — сверху страницы)
- **Видео (около минуты):** [docs/demo.mp4](docs/demo.mp4)
- **Пояснение на одну страницу:** [docs/explainer.pdf](docs/explainer.pdf)

## Что умеет

1. Выбираете, что закупаете и в каком городе, и сразу видите трёх поставщиков, которым стоит позвонить первым: телефон, сайт и одна строка «почему».
2. «Подробнее» раскрывает оценку по понятным баллам (работает ли с бизнесом, совпадает ли профиль, есть ли контакты, известны ли условия, какой рейтинг) и условия с сайта: минимальный заказ, цены, доставка, регион, документы. **У каждого условия ссылка на страницу и дословная цитата.** Чего нет на сайте, показано как «неизвестно» и попадает в список «спросить при звонке».
3. «В сравнение» собирает выбранные компании в одну таблицу; к каждой можно написать заметку и скопировать список коллеге.
4. Ниже свёрнуты все найденные компании с фильтрами и короткое описание того, как работает сбор.

## Почему такой формат

Самое трудное в этой задаче не интерфейс, а данные. Найти компании несложно; сложно не выдумать им условия. Если спросить у нейросети «кто продаёт упаковку в Екатеринбурге и какой у них минимальный заказ», она уверенно ответит, и часть ответа окажется неправдой. Для закупщика это хуже, чем пустое поле: он позвонит с неверными ожиданиями.

Поэтому я разделил сервис на две части:

- **Сборщик** (Python, этот репозиторий) — конвейер, который ищет компании в справочнике, читает их сайты и проверяет каждый факт.
- **Страница** — быстрый интерфейс поверх собранных данных: три поставщика для звонка, подробности, сравнение, заметки. Открывается по ссылке, без установки и регистрации.

Сборщик не отвечает на вопрос «из головы»: модель только раскладывает уже скачанный текст сайта по полям, а код проверяет, что цитата действительно есть на странице. Не нашлась — поле выбрасывается.

## Как работает сборщик

```
категория + город
   │
   ▼
1. Поиск в 2ГИС        запросы по категории («одноразовая посуда оптом», «мясо оптом»…)
   │                   филиалы одной компании склеиваются; компании без нужной рубрики отсекаются
   ▼
2. Карточка 2ГИС       телефоны, почта, сайт, мессенджеры, рейтинг и число отзывов
   │
   ▼
3. Сайт компании       главная + до 3 страниц про доставку, опт, документы
   │                   модель извлекает поля с дословной цитатой → проверка цитаты кодом
   ▼
4. Оценка              сумма баллов с подписями (максимум 100)
   │
   ▼
data/suppliers.json  →  web/build.py  →  страница
```

**Оценка «кому звонить первым»** — сумма понятных частей, без чёрного ящика:

| Часть | Баллы | Откуда |
|---|---|---|
| Работает с бизнесом (опт, производство, торговый дом) | до 30 | тип компании в 2ГИС + фраза на сайте |
| Профиль совпадает с категорией | до 20 | основная рубрика в 2ГИС |
| До компании легко достучаться | до 15 | телефон, почта, сайт, мессенджер |
| Условия известны до звонка | до 15 | минимальный заказ, цены, доставка, регион, документы на сайте |
| Репутация | до 20 | рейтинг с поправкой на число отзывов: 4.9 по 3 отзывам весит меньше, чем 4.6 по 300 |
| Скорее не для общепита | −30 | например, типография мерча в выдаче по «упаковке» |

**Надёжность.** Повторы с паузой при сбоях справочника и сайтов, общий таймаут на компанию (медленный сайт не держит весь прогон), проверка `finish_reason` у модели, учёт стоимости каждого вызова по данным OpenRouter.

## Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run playwright install chromium-headless-shell   # один раз
export OPENROUTER_API_KEY=...                       # без ключа сайты не разбираются, остальное работает
uv run supplier-finder collect --city ekaterinburg --category packaging
uv run supplier-finder collect --all                # все категории во всех городах
uv run python web/build.py                          # собрать страницу в dist/index.html
uv run --group dev pytest                           # офлайн-тесты: проверка цитат и оценки
```

Города: `ekaterinburg`, `chelyabinsk`, `tyumen`. Категории: `packaging`, `vegetables`, `meat`, `fish`, `dairy`. Новая категория — одна запись в `src/supplier_finder/categories.py`: запросы для справочника и рубрики, которые считаются подходящими.

## Ограничения прототипа

- **Это снимок.** Страница показывает данные, собранные заранее. Новый город или категорию нужно один раз прогнать сборщиком (около минуты на пару «категория + город»).
- **Справочник читается через публичные страницы 2ГИС.** Для рабочей версии нужен официальный API 2ГИС (платный ключ); формат записи не меняется.
- **Сайты бывают пустыми.** У многих поставщиков условия только в прайсе по запросу. Это честно видно как «неизвестно» и превращается в вопрос для звонка.
- **Заметки и сравнение хранятся в браузере.** Для команды их нужно перенести в общую базу.

## Что было бы в полной версии

- Запрос из интерфейса: выбрал категорию и город, через минуту получил свежую выдачу (очередь задач + тот же конвейер).
- Второй источник поиска (Яндекс Карты, отраслевые каталоги) и склейка дублей между источниками.
- Общее сравнение и история контактов для команды закупок; напоминания «прайс обещали прислать в пятницу».
- Запрос прайса в один клик: письмо поставщику по шаблону, ответ разбирается в те же поля.
- Еженедельное обновление снимка и сигнал, если у поставщика изменились условия или упал рейтинг.

## Устройство репозитория

```
src/supplier_finder/
  twogis.py      поиск и карточки в 2ГИС (headless-браузер, повторы)
  site.py        чтение сайта: главная + страницы про доставку, опт, документы
  extract.py     извлечение полей моделью + проверка цитат
  score.py       оценка с подписями и «что спросить при звонке»
  categories.py  категории и города
  schema.py      типизированная запись поставщика (Pydantic)
  cli.py         конвейер целиком
web/
  template.html  страница (без сборки, без фреймворков)
  build.py       встраивает data/suppliers.json в страницу
data/suppliers.json  текущий снимок
tests/               офлайн-тесты
```
